PART 1 — COMPLETE FRANCHISE ARCHITECTURE
================================================================================

1. What is a Franchise in Cinema Network?
In Cinema Network, a Franchise is a logical grouping of related movies and TV series that share a common narrative universe, saga, or collection (for example: "Marvel Cinematic Universe", "Harry Potter", "Breaking Bad Universe", "John Wick").

2. Why does the website have a Franchise system?
The Franchise system allows users to discover and explore connected titles in chronological or release order, view overall collection stats (total titles, release year range, average rating), and track their watch progress across a franchise. On the homepage, it showcases curated collections in a high-impact horizontal stacked-poster carousel.

3. What pages/components use franchises?
- Homepage Carousel (`src/components/FranchisesCarousel.tsx` rendered on `src/pages/Home.tsx`)
- Franchise Details Page (`src/pages/FranchiseDetails.tsx` mapped to route `/franchise/:name`)
- Content Detail Page (`src/pages/Detail.tsx` displaying the "Franchise Collection" section)
- Admin Franchise Manager (`src/components/admin/AdminFranchises.tsx` inside `src/pages/admin/Dashboard.tsx`)
- Admin Content Form (`src/pages/admin/ContentForm.tsx` offering franchise autocomplete datalist and TMDB collection auto-fill)

4. What database tables/fields represent franchises?
There is NO separate `franchises` relational table. Franchises are represented using denormalized text and integer fields directly inside the `content` table in Supabase PostgreSQL:
- `franchise` (text): Primary franchise name
- `franchise_name` (text): Duplicate/alias franchise name field for compatibility
- `franchise_id` (text): Optional string identifier
- `franchise_order` (integer): Display/chronological index within the franchise
- `franchise_description` (text): Description text explaining the universe
Homepage franchise collections are pre-compiled and stored as a JSON dataset in the `homepage_cache` table under key `'franchises'`.

5. How are franchises identified?
Franchises are identified primarily by exact or normalized text string matching on the `franchise` / `franchise_name` fields.

6. How are titles connected to franchises?
Titles are connected to a franchise by having their `franchise` or `franchise_name` column populated with the exact string name of the franchise.

7. How are franchises displayed?
- Homepage: Rendered as stacked 3D poster cards with title, title count, year range, average rating, and description overlay inside `FranchisesCarousel`.
- Franchise Details Page: Rendered as a dedicated collection hero view with watch progress tracking, title count, total duration, and a sorted grid/list of titles.
- Content Detail Page: Rendered as a "Franchise Collection" sidebar/banner card with quick links to explore the franchise.

8. How are franchises created?
- Automatically: When a movie is fetched from TMDB that contains `belongs_to_collection.name`, or matching keywords from `KNOWN_FRANCHISES` during cache generation.
- Manually: Via Admin Dashboard (`AdminFranchises.tsx` or `ContentForm.tsx`), where an admin enters a franchise name and assigns content items to it.

9. How are franchises edited?
An admin edits a franchise name or description in `AdminFranchises.tsx`. Saving updates `franchise`, `franchiseName`, and `franchiseDescription` across all database rows matching that franchise name via batch updates.

10. How are franchises deleted?
There is no "DELETE FROM franchises" table operation because no franchise table exists. To remove a franchise, an admin removes all titles from the franchise (setting `franchise` to `''`), or deletes all content items associated with it. When a franchise has 0 titles in the database, it disappears from queries and carousels.

11. How are franchise relationships maintained?
Relationships are maintained by updating the `franchise` text field on content rows. Editing or clearing the text field instantly connects or disconnects the title.

12. Is TMDB involved?
Yes. During movie metadata ingestion or TMDB search/import (`/api/tmdb/details/...`), if TMDB returns a `belongs_to_collection` object, its `name` is automatically assigned to `franchise` and `franchiseName`.

13. Is the Franchise system automatic, manual, or both?
Both. It automatically extracts collections from TMDB and auto-detects known franchise titles, while allowing admins full manual control to create, edit, rename, reorder, or reassign franchises.

14. Is franchise information cached?
Yes. Homepage franchise carousel datasets are compiled server-side and cached in the `homepage_cache` PostgreSQL table (key `'franchises'`) and stored in server memory (`homepageMemoryCache.franchises`).

15. Is Firestore involved?
Secondary replication only. Real content documents containing `franchise` fields are replicated to Firestore asynchronously via `replicateToFirestore`. Homepage franchise cache is Supabase-ONLY.

16. Is Supabase involved?
Yes. Supabase PostgreSQL is the absolute source of truth for all content items, franchise fields, and homepage franchise cache.

17. What happens when a movie is added or edited?
When content is saved/updated via `saveContent()`, Supabase updates the `content` table row. The server then triggers `updateHomepageOnContentMutation()`, rebuilding the homepage franchise cache and syncing the content document to Firestore non-blockingly.

PART 4 — HOW A MOVIE IS ASSOCIATED WITH A FRANCHISE
================================================================================

Cinema Network determines franchise association primarily using string text matching on the `franchise` or `franchise_name` database columns:

```text
Movie Record in Supabase
↓
Check `franchise` / `franchise_name` column
↓
If populated (e.g. "Marvel Cinematic Universe")
↓
Query: WHERE franchise = 'Marvel Cinematic Universe' OR franchise_name = 'Marvel Cinematic Universe'
↓
Sort results: ORDER BY franchise_order ASC or year ASC
```

If a movie does not have `franchise` explicitly populated, the cache builder (`server-db.ts`) and carousel (`FranchisesCarousel.tsx`) run a secondary keyword check matching `item.title` against `KNOWN_FRANCHISES` array ("John Wick", "Harry Potter", "Spider-Man", etc.).

PART 5 — TMDB FRANCHISE / COLLECTION DATA
================================================================================

1. Does TMDB provide franchise/collection data?
Yes. TMDB includes a `belongs_to_collection` object in movie detail responses (containing `id`, `name`, `poster_path`, `backdrop_path`).

2. Is the TMDB collection ID stored?
No specific `tmdb_collection_id` column exists in `schema.content`. The collection name is extracted and stored.

3. Is the collection name stored?
Yes. `belongs_to_collection.name` is stored in both `franchise` and `franchise_name` columns.

4. Is it automatically retrieved during movie ingestion?
Yes. When importing from TMDB in `ContentForm.tsx` or during database enrichment in `server.ts`, `details.belongs_to_collection.name` is extracted.

5. Is it retrieved when metadata is enriched?
Yes. Enriched metadata updates `franchise` and `franchiseName` if they are empty.

6. Can a movie be associated with a franchise automatically?
Yes, via TMDB collection auto-fill or title keyword matching.

7. What happens if TMDB does not provide collection data?
The franchise field remains blank unless manually entered by an admin or matched by `KNOWN_FRANCHISES`.

8. Can the admin manually override it?
Yes. Admins can edit the `franchise` text field in `ContentForm.tsx` or `AdminFranchises.tsx` at any time.

PART 16 — FRANCHISE DUPLICATES
================================================================================

1. Can two franchises have the same name?
In string representation, typing the exact same string merges titles into the same franchise. However, case differences ("Marvel" vs "marvel") or trailing spaces create separate groups in raw string matching.
2. Unique ID?
No separate franchise entity ID exists; string matching is used.
3. Duplicate Detection:
`AdminFranchises.tsx` groups by `(item.franchise || item.franchiseName || '').trim()`.

================================================================================
PART 17 — FRANCHISE IDENTIFICATION PROBLEMS
================================================================================

1. Text Sensitivity:
The system relies on exact string equality. Variations like "MCU", "Marvel Cinematic Universe", or "Marvel Universe" are treated as distinct franchises unless manually edited to match.
2. Case Sensitivity:
SQL queries in `getFranchiseContentServer` use `eq(schema.content.franchise, franchiseName)` (exact case equality), whereas fallback searches use `.toLowerCase()`.
3. Lack of Entity Table:
Because there is no primary key `franchise_id` table, renaming a franchise requires updating every individual content row in the database.

================================================================================
PART 18 — FRANCHISE + NEW MOVIE
================================================================================

When a new movie is added to an existing franchise:
1. `saveContent()` inserts the row into Supabase `content` table with `franchise = 'Franchise Name'`.
2. `buildAllHomepageDatasets(true)` runs asynchronously, inserting the new movie into the franchise group in `homepage_cache`.
3. Replicating function `replicateToFirestore()` queues/writes the document to Firestore.
4. Next request to `/api/content/franchise/:name` returns the new movie immediately.

================================================================================
PART 19 — FRANCHISE + EDITED MOVIE
================================================================================

When an admin changes a movie from Franchise A to Franchise B:
1. Supabase updates the row with `franchise = 'Franchise B'`.
2. `buildAllHomepageDatasets(true)` rebuilds `homepage_cache`.
3. The movie drops out of Franchise A results and appears under Franchise B.

================================================================================
PART 20 — FRANCHISE + DELETED MOVIE
================================================================================

When a movie belonging to a franchise is deleted:
1. `deleteContent(id)` deletes the row from Supabase `content`.
2. `buildAllHomepageDatasets(true)` removes the item from the franchise card stack in cache.
3. If that was the last movie in the franchise, the franchise automatically ceases to exist in queries and carousels.

================================================================================
PART 21 — EMPTY FRANCHISE
================================================================================

A franchise with 0 movies does not exist in the database because franchises are derived dynamically from content rows. It will not appear on the homepage carousel or in search results.

================================================================================
PART 22 — FRANCHISE SEARCH
================================================================================

1. Admin Search (`AdminFranchises.tsx`):
Filters global content by checking if `item.franchise` includes the search query.
2. Detail Page Fallback Search (`FranchiseDetails.tsx`):
Calls `/api/content/search?q=cleanName` if exact franchise match fails.
3. API Endpoint (`/api/content/search`):
Queries Supabase using `ilike(schema.content.franchise, pattern)` and `ilike(schema.content.franchiseName, pattern)`.

================================================================================
PART 35 — CURRENT BUGS / RISKS
================================================================================

1. Text Case Sensitivity in SQL Query: `getFranchiseContentServer()` uses `eq(schema.content.franchise, franchiseName)`, which requires exact case string matching. If a title has "harry potter" lowercase, exact query won't match "Harry Potter".
2. Denormalized Renaming Cost: Renaming a franchise requires updating every matching row in the `content` table individually.
3. Duplicate Franchise Card Generation: In `FranchisesCarousel.tsx` client-side grouping, minor trailing space variations can cause multiple cards for the same franchise if raw data isn't trimmed.

PART 37 — FINAL ANSWERS
================================================================================

1. How does Cinema Network identify a franchise?
By exact text string matching on the `franchise` and `franchise_name` columns in the `content` table.

2. How does it group movies into a franchise?
By collecting all content items where `franchise = 'Franchise Name'`.

3. Where is the relationship stored?
In the `content` table (`franchise`, `franchise_name`, `franchise_order` columns) and precomputed `homepage_cache` table.

4. Does TMDB automatically provide the franchise information?
Yes, via the `belongs_to_collection.name` field when details are fetched from TMDB.

5. Can admin manually create a franchise?
Yes, in `AdminFranchises.tsx` or by entering a franchise name in `ContentForm.tsx`.

6. Can admin manually edit a franchise?
Yes, in `AdminFranchises.tsx`.

7. Can admin manually delete a franchise?
Yes, by clearing or reassigning all titles associated with that franchise name.

8. Can admin reorder franchises?
In individual franchises, movies can be ordered via `franchiseOrder`. On the homepage, franchises are automatically ordered by title count and average rating.

9. How is a movie added to an existing franchise?
By setting its `franchise` field to the exact string name of the existing franchise.

10. How is a movie removed from a franchise?
By setting its `franchise` field to an empty string `""`.

11. How are franchise movies ordered?
By `franchise_order ASC` in the database, and `year ASC` on the frontend.

12. How does the homepage get its franchise list?
From `GET /api/home/content`, which reads the precomputed `'franchises'` key from the `homepage_cache` table.

13. How does the franchise detail page get its movies?
From `GET /api/content/franchise/:name`, which queries Supabase `content` table.

14. How is franchise data cached?
Compiled server-side into JSON objects grouped by category and saved to `homepage_cache`.

15. Where is the cache stored?
In Supabase PostgreSQL `homepage_cache` table and server RAM (`homepageMemoryCache`).

16. Is franchise cache stored in Firestore?
No. Verified: Franchise homepage cache is strictly Supabase-only.

17. What invalidates the cache?
Any content creation, edit, deletion, or admin batch update calls `buildAllHomepageDatasets(true)`.

18. What happens when a new movie is added?
`saveContent()` writes the movie row and triggers an asynchronous rebuild of `homepage_cache`.

19. What happens when a movie is edited?
Supabase updates the row, and the homepage franchise cache is automatically rebuilt.

20. What happens when a movie is deleted?
The row is deleted from Supabase, and the homepage cache rebuilds without that movie.

21. What happens when a franchise is deleted?
When all titles are removed, 0 rows match that franchise name, so it automatically disappears.

22. Can duplicate franchises exist?
String variations (e.g. "MCU" vs "Marvel Cinematic Universe") can create separate franchise cards unless normalized by the admin.

23. What database is the source of truth?
Supabase PostgreSQL.

24. What API endpoints control franchises?
- `GET /api/content/franchise/:name`
- `GET /api/home/content`
- `POST /api/content`

25. What exact files control the Franchise system?
- `src/db/schema.ts`
- `server-db.ts`
- `server.ts`
- `src/components/FranchisesCarousel.tsx`
- `src/pages/FranchiseDetails.tsx`
- `src/pages/Detail.tsx`
- `src/components/admin/AdminFranchises.tsx`
- `src/pages/admin/ContentForm.tsx`

================================================================================
FRANCHISE SYSTEM IN SIMPLE TERMS
================================================================================

In Cinema Network, a "Franchise" is not a separate database table. Instead, it is a shared text label (like "Harry Potter" or "Marvel Cinematic Universe") saved directly on each movie or TV series in the database (`franchise` column).

When a movie is imported from TMDB, Cinema Network automatically checks if TMDB lists a collection name (e.g. "The Dark Knight Collection") and saves it as the movie's franchise. Administrators can also type any custom franchise name or use the Admin Franchise Manager tool to group movies together.

On the website homepage, the server groups movies with the same franchise name, builds a 3D stacked poster card showing the total title count, release year range, and average rating, and saves this ready-to-render list into Supabase's `homepage_cache` database table for instant loading.

When a user clicks a franchise card on the homepage, they are taken to `/franchise/:name`, which fetches all movies belonging to that franchise name from Supabase, sorted by release year, and shows their watch progress across the franchise.

Editing or clearing the franchise text label on movies instantly creates, updates, or deletes franchises across the entire website.
